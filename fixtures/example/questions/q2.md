# Question
During the voice interview, the language model has to call a tool before it asks each question, and the server keeps track of where the interview is. What does that give us compared with simply writing the rules in the prompt?

# Answer
Rules in a prompt are suggestions; the model can skip a question, ask two follow-ups or end early. Keeping the state on the server and making the model request each step through a tool turns those rules into code: the server refuses an out-of-order question, a second follow-up or an early ending, and tells the model why so it can correct itself. The tool calls also give a reliable signal of which question is active, which is used to tag every turn of the transcript for the evaluator. A strong answer mentions both enforcement and the reliable record.

# Context
Comes from `src/interview/flow.py`. `InterviewFlow` holds the current question index and whether the follow-up was used; `start_question`, `ask_followup` and `end_interview` return either the wording to say or an error. `src/interview/session.py` reads `flow.question_id` when recording each turn.

# Follow-up
## Question
What happens if the model skips the tool call and just asks the next question out loud?

## Answer
The server state does not advance, so the new question and its answer are recorded under the previous question, and the evaluator may grade them against the wrong reference answer. The model cannot be fully prevented from speaking freely, so the design has to detect and tolerate it: compare what was said with the expected question wording, fall back to tagging by order, log a warning, or have the evaluator read the whole transcript rather than trust the tags blindly.

## Context
`TranscriptRecorder.add()` in `src/interview/recorder.py` tags a turn with whatever `flow.question_id` is at that moment. There is currently no fallback when a tool call is skipped.
