# Question
The interview transcript has to be saved when the interview ends normally, when the candidate closes the browser, and when a time limit is reached. How would you make sure it is saved in all three cases, and what could still go wrong?

# Answer
Give the session a single exit path. Every way of ending, whether the goodbye, a disconnect or the timer, signals the same stop condition, and the save happens in a finally block that runs however the session ends, before the connection is closed. What can still go wrong: the transcript only lives in memory until then, so a crash or a killed process loses everything; writing each turn to disk as it happens fixes that. The last words may also be missing if the speech recogniser had not finished them, and the write itself can fail.

# Context
Comes from `run_interview()` in `src/interview/session.py`. Three tasks (output loop, input loop, watchdog) each set one `stop` event; the `finally` block cancels them, calls `recorder.save()`, then notifies the browser and closes the socket.
