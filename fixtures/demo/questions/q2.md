# Question
We publish an event to a queue after saving an order to the database. How would you make sure the two never get out of sync?

# Answer
Saving and publishing are two separate systems, so a crash between them loses the event, and publishing first can announce an order that was never saved. The usual fix is a transactional outbox: write the event to an outbox table in the same database transaction as the order, and have a separate relay publish it and mark it sent. Consumers must be idempotent because delivery becomes at-least-once.

Sample fixture. Comes from `orders/service.py`, where `create_order()` commits and then calls `publisher.publish()` directly.
