# Question
One endpoint in this service got slow as the orders table grew. Walk me through how you would find the cause.

# Answer
Start from evidence, not guesses: check latency percentiles and traces to see whether time goes to the database, to an outbound call or to the application. For the database, look at the slow query log and run explain analyze on the suspect query. Typical causes here are a missing index on the filter or sort column, an N plus one query pattern from the ORM, and unbounded result sets without pagination. Fix, then confirm with the same measurement.

# Context
Sample fixture. Comes from `orders/api.py`, where `list_orders()` filters by customer and sorts by creation date, then loads line items per order in a loop.

# Follow-up
## Question
Suppose it turns out to be one query per order for the line items. How would you fix that?

## Answer
Load the line items for all orders on the page in one query, either with a join or with a second query using an in clause on the order ids, which in the ORM is eager loading. Combine it with pagination so the batch stays bounded.

Sample fixture. The loop is in `list_orders()`; the ORM supports `selectinload`.
